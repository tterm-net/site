post.open-source.prose.2 = Since October 11, all of tTerm's code comes out under AGPL v3: tTerm Web in full, both the page and the server, the agent for computers, the Telegram bot and this site. tTerm for your computer, which we are building now, has been under it since its first version. Before that, the bot, the agent and the site came out under MIT. Versions already released under MIT keep it: a license cannot be taken back after the fact. AGPL applies to everything new.
post.open-source.prose.3 = Why even the server is open
post.open-source.prose.4 = tTerm connects to your machines. On a server it signs in as the user tterm with sudo, which means it gets root. A service with that kind of access should not be taken at its word, so everything that has to do with it is open: the core, the separate program that signs certificates, the installer and the agent.
post.open-source.prose.5 = Any promise on our main page can be checked against the code. A certificate lives for two minutes and is good for one server only. The CA keys are kept in a separate process with no network. The installer adds one line to <code>authorized_keys</code> and does not touch <code>sshd_config</code>. The server at app.tterm.net updates straight from the open repository, so what is on GitHub is exactly the code that runs.
post.open-source.prose.6 = Often only the app is open, and the server is kept closed. For a terminal with root on other people's machines, that seems wrong to us.
post.open-source.prose.7 = Why AGPL and not MIT
post.open-source.prose.8 = MIT allows almost anything, including taking the code, improving it and running it as a closed service. The people who connect their servers to such a service then have no way of knowing whom they gave root to, and how.
post.open-source.prose.9 = AGPL does not allow that: whoever runs a modified copy of tTerm as a service for others must open its code to their users. Any service built on our code stays as transparent as ours.
post.open-source.prose.10 = None of this binds you. Connect your machines, work, set tTerm up on your own server: the license only comes into play if you pass tTerm on to other people or run a modified version as a service for them.
post.open-source.prose.11 = So why pay
post.open-source.prose.12 = You will pay for the service, not for access to the code. Keeping tTerm running every day takes servers in the EU and copies of the database, email, support, and someone keeping an eye on updates. That is where the money from paid plans will go, and we will tell you about the plans in advance. While tTerm is in beta, it is free for everyone.
post.open-source.prose.13 = You can run your own copy of tTerm: AGPL allows that. But most people need a terminal, not one more service to host, update and back up themselves.
post.open-source.prose.14 = Other open projects live this way too. In 2020 Plausible moved from MIT to AGPL so that companies would not build competing services on its code without giving anything back. In 2021 Grafana moved to AGPL from Apache 2.0. Both sell a cloud version of their open code.

# prose
post.tterm-web.prose.1 = Why a browser when there is a bot
post.tterm-web.prose.2 = The bot is great when all you have is a phone: restart a service, check the disk, answer an installer's question. But longer work wants a big screen: several tabs side by side, vim and htop full screen, a history where yesterday's command is easy to find.
post.tterm-web.prose.3 = That is what tTerm Web is for. It opens in any browser, on a laptop, a tablet or a phone, and needs nothing installed on the device you work from.
post.tterm-web.prose.4 = Every command in a block of its own
post.tterm-web.prose.5 = In an ordinary terminal everything runs together into one stream, and you have to find by eye where one command ended and the next began. In tTerm every command comes as a block of its own: the command, its output, the exit code, the time, the directory and the git branch.
post.tterm-web.prose.6 = You can copy a block together with its output, fold it or run it again. While a command runs, its output streams live, and once it finishes the block settles into plain text that is easy to select and copy.
post.tterm-web.prose.7 = An input line like an editor
post.tterm-web.prose.8 = At the bottom there is an input line of its own. Shift+Enter starts a new line, a command from your history is suggested in grey, Tab completes. History is kept on our side, so it is the same on all your devices.
post.tterm-web.prose.9 = Above the line you see where you are: the directory and the branch. Click them and pick another from the list, and <code>cd</code> or <code>git switch</code> runs as an ordinary block. And before a dangerous command, the kind that leaves nothing to fix, tTerm asks again.
post.tterm-web.prose.10 = vim, htop and sudo
post.tterm-web.prose.11 = Full-screen programs open across the whole terminal area and work as usual, and so does sudo. If you do not want blocks, there is a classic mode: one continuous terminal, the way you are used to.
post.tterm-web.prose.12 = The terminal does not close with the tab
post.tterm-web.prose.13 = The terminal lives on our server, not in your browser. Close your laptop in the middle of a build on a server: the build carries on and its output is kept. Open tTerm on another device, and the terminal is right there.
post.tterm-web.prose.14 = Tabs from different projects open side by side and carry the project code: P/web-01, A/api-prod. Cmd+K opens the palette: go to any terminal, open a new one on any machine or run an action.
post.tterm-web.prose.15 = How to connect a machine
post.tterm-web.prose.16 = A Linux server connects with one command. tTerm Web shows it when you add a machine, and you run it on the server:
post.tterm-web.prose.17 = The installer creates a user called tterm on the server, adds one line to its <code>authorized_keys</code> and gives it sudo in a file of its own in <code>/etc/sudoers.d</code>. It does not touch <code>sshd_config</code>, does not restart sshd and opens no ports. A few seconds later the server shows up in your list.
post.tterm-web.prose.18 = A computer on macOS or Linux connects through a small agent. It runs as your user and dials out to our server by itself, so no inbound ports are needed and the computer can sit behind NAT. The agent uninstalls with one command.
post.tterm-web.prose.19 = Security
post.tterm-web.prose.20 = We connect to your machines, so we built access to be easy to give and just as easy to take back.
post.tterm-web.prose.21 = <strong>Your keys are not needed.</strong> For every connection tTerm signs a new SSH certificate with your name in it. It is good for that one server only and stops working two minutes later.
post.tterm-web.prose.22 = <strong>Signing kept apart.</strong> The keys we sign with live in a separate process with no network. The main program cannot read them, only ask for a signature, and every signature is logged.
post.tterm-web.prose.23 = <strong>No middlemen.</strong> The tTerm server is in the EU. The page and the terminals go straight to it: Cloudflare only handles our DNS and never sees your commands.
post.tterm-web.prose.24 = <strong>Easy to take back.</strong> Remove a server in tTerm, and it takes its own access off the server; if the server does not answer, tTerm shows the command that does it there. How to remove everything else the installer set up is written at the top of the script itself.
post.tterm-web.prose.25 = <strong>Open source.</strong> tTerm Web and the agent are open source under the AGPL-3.0 license. The install script is short and worth reading before you run it.
post.tterm-web.prose.26 = What it costs
