post.tterm-web.prose.4 = 명령마다 별도의 블록
post.tterm-web.prose.5 = 일반 터미널에서는 모든 것이 하나의 흐름으로 이어져서, 한 명령이 어디서 끝나고 다음 명령이 어디서 시작됐는지 눈으로 찾아야 해요. tTerm에서는 명령마다 별도의 블록으로 나와요. 명령, 출력, 종료 코드, 실행 시간, 디렉터리, git 브랜치가 한 블록에 담겨요.
post.tterm-web.prose.6 = 블록은 출력까지 통째로 복사하거나, 접거나, 다시 실행할 수 있어요. 명령이 실행되는 동안에는 출력이 실시간으로 흘러나오고, 끝나면 블록은 선택하고 복사하기 쉬운 일반 텍스트로 정리돼요.
post.tterm-web.prose.7 = 에디터 같은 입력 줄
post.tterm-web.prose.8 = 맨 아래에는 별도의 입력 줄이 있어요. Shift+Enter로 줄을 바꾸고, 기록에 있는 명령이 회색으로 제안되며, Tab으로 자동 완성돼요. 기록은 저희 쪽에 저장되기 때문에 모든 기기에서 같아요.
post.tterm-web.prose.9 = 입력 줄 위에는 지금 위치, 즉 디렉터리와 브랜치가 보여요. 이걸 클릭해서 목록에서 다른 걸 고르면 <code>cd</code>나 <code>git switch</code>가 일반 블록으로 실행돼요. 그리고 되돌릴 수 없는 위험한 명령 앞에서는 tTerm이 한 번 더 물어봐요.
post.tterm-web.prose.10 = vim, htop, sudo

post.tterm-web.prose.14 = 여러 프로젝트의 탭이 나란히 열리고, P/web-01, A/api-prod처럼 프로젝트 코드가 붙어요. Cmd+K를 누르면 팔레트가 열려요. 어떤 터미널로든 이동하거나, 아무 머신에서나 새 터미널을 열거나, 동작을 실행할 수 있어요.
post.tterm-web.prose.15 = 머신 연결 방법

post.tterm-web.prose.17 = 설치 스크립트는 서버에 tterm이라는 사용자를 만들고, 이 사용자의 <code>authorized_keys</code>에 한 줄을 추가하고, <code>/etc/sudoers.d</code> 안의 별도 파일로 sudo 권한을 줘요. <code>sshd_config</code>는 건드리지 않고, sshd를 재시작하지 않으며, 포트도 열지 않아요. 몇 초 뒤 서버가 목록에 나타나요.
post.tterm-web.prose.18 = macOS나 Linux 컴퓨터는 작은 에이전트로 연결돼요. 에이전트는 사용자 계정으로 실행되고 저희 서버로 스스로 연결하기 때문에, 인바운드 포트가 필요 없고 컴퓨터가 NAT 뒤에 있어도 돼요. 에이전트는 명령 한 줄로 제거할 수 있어요.

post.tterm-web.prose.23 = <strong>중개자 없음.</strong> tTerm 서버는 EU에 있어요. 페이지와 터미널은 이 서버로 바로 연결돼요. Cloudflare는 DNS만 맡고 있어서 명령을 전혀 보지 못해요.
post.tterm-web.prose.24 = <strong>회수도 쉽게.</strong> tTerm에서 서버를 삭제하면 tTerm이 그 서버에서 자기 접근 권한을 직접 제거해요. 서버가 응답하지 않으면 서버에서 실행할 명령을 tTerm이 보여 줘요. 설치 스크립트가 설정한 나머지를 제거하는 방법은 스크립트 맨 위에 적혀 있어요.
post.tterm-web.prose.25 = <strong>오픈 소스.</strong> tTerm Web과 에이전트는 AGPL-3.0 라이선스로 공개된 오픈 소스예요. 설치 스크립트는 짧으니 실행하기 전에 한번 읽어 보세요.
