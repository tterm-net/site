# security
index.security.1 = セキュリティ
index.security.2 = 鍵は預かりません。<br>ポートも開けません。
index.security.3 = マシンへのアクセス権は簡単に付与でき、同じくらい簡単に取り消せます。そのしくみを紹介します。
index.security.4 = 有効期間 2 分の証明書
index.security.5 = 接続のたびに、あなたの名前が入った専用の SSH 証明書を発行します。使えるのはそのサーバー 1 台だけです。お使いの鍵は一切必要ありません。
index.security.6 = 署名を分離
index.security.7 = CA の鍵は、ネットワークにつながっていない別のプロセスにあります。コアはこの鍵を読めず、署名を依頼できるだけです。署名はすべて記録されます。
index.security.8 = sshd_config はそのまま
index.security.9 = 信頼の設定は、1 人のユーザーの authorized_keys に書く 1 行だけです。何も再起動しません。
index.security.10 = 接続は内側から
index.security.11 = コンピューターのエージェントは自分から外へ接続するので、受信ポートは必要ありません。アンインストールもコマンド 1 つです。
index.security.12 = 第三者を介さない
index.security.13 = ページもターミナルも、EU にある tTerm のサーバーに直接つながります。Cloudflare は DNS として使っているだけで、コマンドを目にすることはありません。
index.security.14 = tTerm Web とエージェントは AGPL のオープンソースです。インストールスクリプトは短いので、実行する前にぜひ読んでください。

# faq
index.faq.1 = よくある質問
index.faq.2 = 自分のコンピューターに何かをインストールする必要はありますか？
index.faq.3 = いいえ、ブラウザーがあれば十分です。インストールが必要なのは接続先のマシンだけで、サーバーにはコマンドを 1 つ実行し、コンピューターには小さなエージェントを入れます。
index.faq.4 = どんなデータを保存していますか？
index.faq.5 = 履歴の表示に使うコマンドとその出力（30 日間）、それにサインインの記録です。鍵やパスワードは保存しません。詳しくは<a href="/privacy/">プライバシーポリシー</a>をご覧ください。
index.faq.6 = 一般的な SSH クライアントと比べて、何が良いのですか？
index.faq.7 = どのブラウザーからでも使え、デバイスに鍵を置く必要がありません。ノートパソコンを閉じてもターミナルは切れません。さらに、コマンドはすべてブロックとして表示されるので、コピーも再実行も簡単です。
index.faq.8 = tTerm のアクセス権を取り消すにはどうすればよいですか？
index.faq.9 = tTerm でサーバーを削除すると、tTerm は自身のアクセス権をそのサーバーから取り除きます。サーバーが応答しない場合は、サーバー上で同じことを行うためのコマンドを tTerm が表示します。インストーラーが設定したそれ以外のものを削除する方法は、スクリプトの冒頭に書かれています。エージェントは、コマンド 1 つでコンピューターから削除できます。
index.faq.10 = Telegram ボットはどうなりますか？
index.faq.11 = 今後も残り、引き続き使えます。チャットの中でそのまま使えるターミナル、<a href="https://t.me/tTermNetBot" target="_blank" rel="noopener">@tTermNetBot</a> です。今のところ、Web アプリとボットは別々に動いています。
index.faq.12 = サポートにはどう連絡すればよいですか？
index.faq.13 = <a href="mailto:support@tterm.net">support@tterm.net</a> までメールでご連絡ください。脆弱性を見つけた場合は、<a href="mailto:security@tterm.net">security@tterm.net</a> 宛てにお送りください。

post.open-source.prose.4 = tTerm はお使いのマシンに接続します。サーバーには sudo 権限を持つユーザー tterm としてログインするので、事実上 root を得ることになります。それほどのアクセス権を持つサービスを、言葉だけで信用すべきではありません。だからこそ、コア、証明書に署名する独立したプログラム、インストーラー、エージェントと、アクセスに関わるものはすべて公開しています。

post.open-source.prose.8 = MIT ではほぼ何でも許されます。コードを持ち出して改良し、非公開のサービスとして運営することもできます。そうなると、そのサービスに自分のサーバーをつないだ人たちには、誰に、どのように root を渡したのかを知るすべがありません。
post.open-source.prose.9 = AGPL ではそれが許されません。tTerm を改変したコピーを他人向けのサービスとして運営する人は、そのコードを利用者に公開しなければなりません。私たちのコードをもとにしたサービスは、どれも私たちと同じように透明であり続けます。
post.open-source.prose.10 = これによって利用者が何かに縛られることはありません。マシンを接続して作業するのも、自分のサーバーに tTerm を立てるのも自由です。ライセンスが関わってくるのは、tTerm をほかの人に配布する場合や、改変したバージョンをほかの人向けのサービスとして運営する場合だけです。

post.tterm-web.prose.4 = コマンドごとに独立したブロック
post.tterm-web.prose.5 = 普通のターミナルでは、すべてが 1 本の流れにつながってしまい、どこで 1 つのコマンドが終わり、次のコマンドが始まったのかを目で探す必要があります。tTerm では、コマンドごとに独立したブロックになります。コマンド本体、出力、終了コード、時間、ディレクトリ、git のブランチがひとまとまりです。
post.tterm-web.prose.6 = ブロックは出力ごとコピーでき、折りたたんだり再実行したりもできます。コマンドの実行中は出力がリアルタイムで流れ、終了するとブロックは、選択やコピーのしやすいプレーンテキストに落ち着きます。

post.tterm-web.prose.8 = 画面の下には専用の入力行があります。Shift+Enter で改行でき、履歴にあるコマンドがグレーで候補表示され、Tab で補完できます。履歴は tTerm 側で保存しているので、どのデバイスでも同じ履歴を使えます。
post.tterm-web.prose.9 = 入力行の上には、いまいる場所が表示されます：ディレクトリとブランチです。クリックして一覧から別のものを選ぶと、<code>cd</code> や <code>git switch</code> が通常のブロックとして実行されます。また、取り返しのつかない危険なコマンドの前には、tTerm がもう一度確認します。

post.tterm-web.prose.14 = 別々のプロジェクトのタブを並べて開け、各タブには P/web-01、A/api-prod のようにプロジェクトのコードが付きます。Cmd+K でコマンドパレットが開き、任意のターミナルへの移動、任意のマシンでの新しいターミナルの起動、アクションの実行ができます。
