tTerm がブラウザーで使えるようになりました

すべてのサーバーとコンピューターを 1 つのタブで。コマンドはそれぞれ独立したブロックになり、デバイスに鍵を置く必要もありません。tTerm Web で今できること、マシンの接続方法、今後の予定を紹介します。

2026年10月

10月25日tTerm Web

有料プランを予定していても tTerm のコードを公開する理由

tTerm のコードはすべて、MIT に代わって AGPL v3 で公開されるようになりました。有料プランもまもなく始まります。この 2 つが両立する理由と、サーバーまで公開した理由を説明します。

記事を読む

10月20日tTerm Web

ノート、色分けされたプロジェクト、ターミナルの名前

手順書、チェックリスト、アクセス情報などのノートを、対象のマシンのすぐそばに置けるようになりました。プロジェクトを自分で作って色を付けたり、ターミナルに名前を付けたり、マシンやノートを別のプロジェクトへ移したりもできます。公開から最初の数日で tTerm Web に加わった機能を紹介します。

記事を読む

10月7日ボット

コンピューターのウィンドウが互いに独立しました

サーバーでは以前から、ウィンドウはそれぞれ独立したターミナルでした。一方、エージェントを入れたコンピューターでは、すべてのウィンドウが 1 つのシェルを共有していました。1 つのウィンドウで cd するとほかのウィンドウのディレクトリも変わり、どこかでプログラムが動いているあいだ、ほかのウィンドウは待たされていました。今後は、サーバーと同じく、ウィンドウごとに専用のシェルが割り当てられます。あるウィンドウで開発サーバーを動かしたまま、別のウィンドウで作業できます。

記事を読む

2026年9月

9月30日ボット

実行中のコマンドに応答できるようになりました

これまでは、プログラムに Continue? (Y/n) と聞かれても、答える方法がありませんでした。コマンドが終わるまでメッセージが送信されなかったためです。今後は、コマンドの実行中に入力した内容が、普通のターミナルと同じようにそのコマンドへの入力として渡されます。ボットはそうしたメッセージに 👌 のリアクションを付けます。

記事を読む

9月17日ボット

エージェントがいつものシェルを起動するようになりました：bash でも zsh でも

これまでエージェントは、ユーザーのシェルにかかわらず常に bash を起動していました。2019年から zsh が標準になっている macOS では、それは他人の環境で作業するのと同じことで、インストールしたもののうち半分は見つかりませんでした。

記事を読む

9月3日サイト

tTerm が GitHub の検証済み組織になりました

github.com/tterm-net に Verified バッジが付きました。この組織と tterm.net の運営者が同じであることを、GitHub が確認しました。

記事を読む

9月1日ボット

1 台のマシンで複数のターミナル

同じサーバーで、複数のターミナルを開いておけるようになりました。1 つでログを追い、もう 1 つで作業する、といった使い方ができます。/use では別々の行として表示され、それぞれが専用のシェルを持ちます。片方で cd しても、もう片方のディレクトリは変わりません。

記事を読む

2026年8月

8月31日ボット

tTerm を公開しました

サーバーのためのターミナルを、ここ Telegram で。コマンドを入力するとマシン上で実行され、終了コード、作業ディレクトリ、git のブランチを添えたメッセージで結果が返ってきます。シェルは、前回作業を終えたところを覚えています。

記事を読む

8月28日ボット

ボットを専用サーバーへ移行

ボットは専用のサーバーに移り、ノートパソコンが開いているかどうかに左右されなくなりました。ボットとエージェントのソースコードは公開されています。

8月26日ボット

メッセージ内のボタン

マシンの一覧、メニュー、確認が、メッセージ内のボタンになりました。接続できないマシンは、エラーになるのではなくグレーで表示されます。

8月25日ボット

期限付きのアクセス

アクセスを共有するときに期限を設定できるようになりました。期限が切れたアクセスは自動的に閉じられ、双方に通知が届きます。オーナーは、コマンド履歴全体をファイルとして書き出せます。

8月23日ボット

エージェント経由でコンピューターも

自分から外へ接続する小さなエージェントを介して、コンピューターも接続できるようになりました。今のところ macOS と Linux に対応しています。
