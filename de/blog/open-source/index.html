tTerm Web25. Oktober 2026·4 Minuten Lesezeit

Warum der Code von tTerm offen ist, obwohl kostenpflichtige Tarife kommen

Der gesamte Code von tTerm steht jetzt unter AGPL v3 statt MIT, und bald kommen kostenpflichtige Tarife. Hier erklären wir, warum das eine dem anderen nicht im Weg steht und warum sogar der Server offen ist.

Was sich geändert hat

Seit dem 11. Oktober erscheint der gesamte Code von tTerm unter AGPL v3: tTerm Web vollständig, also Seite und Server, der Agent für Computer, der Telegram-Bot und diese Website. tTerm für deinen Computer, an dem wir gerade arbeiten, steht seit seiner ersten Version unter dieser Lizenz. Davor erschienen Bot, Agent und Website unter MIT. Versionen, die bereits unter MIT veröffentlicht sind, bleiben dabei: Eine Lizenz lässt sich nicht nachträglich zurückziehen. Die AGPL gilt für alles Neue.

Warum sogar der Server offen ist

tTerm verbindet sich mit deinen Maschinen. Auf einem Server meldet es sich als Benutzer tterm mit sudo an, bekommt also root. Einem Dienst mit solchem Zugriff sollte man nicht einfach aufs Wort glauben, deshalb ist alles offen, was damit zu tun hat: der Kern, das separate Programm, das Zertifikate signiert, der Installer und der Agent.

Jedes Versprechen auf unserer Startseite lässt sich am Code überprüfen. Ein Zertifikat lebt zwei Minuten und gilt nur für einen Server. Die CA-Schlüssel liegen in einem separaten Prozess ohne Netzwerk. Der Installer fügt authorized_keys eine Zeile hinzu und rührt sshd_config nicht an. Der Server unter app.tterm.net aktualisiert sich direkt aus dem offenen Repository, also ist das, was auf GitHub liegt, genau der Code, der läuft.

Oft ist nur die App offen, und der Server bleibt geschlossen. Für ein Terminal mit root auf fremden Maschinen halten wir das für falsch.

Warum AGPL und nicht MIT

MIT erlaubt fast alles, auch den Code zu nehmen, zu verbessern und als geschlossenen Dienst zu betreiben. Wer seine Server mit so einem Dienst verbindet, kann dann nicht wissen, wem er root gegeben hat und auf welche Weise.

Die AGPL erlaubt das nicht: Wer eine veränderte Kopie von tTerm als Dienst für andere betreibt, muss den Code für die eigenen Nutzer offenlegen. Jeder Dienst auf Basis unseres Codes bleibt so transparent wie unserer.

Dich bindet nichts davon. Verbinde deine Maschinen, arbeite, setz tTerm auf deinem eigenen Server auf: Die Lizenz kommt erst ins Spiel, wenn du tTerm an andere weitergibst oder eine veränderte Version als Dienst für sie betreibst.

Wozu also bezahlen

Bezahlen wirst du für den Dienst, nicht für den Zugang zum Code. Damit tTerm jeden Tag läuft, braucht es Server in der EU und Kopien der Datenbank, E-Mail, Support und jemanden, der die Updates im Blick behält. Dafür ist das Geld aus den kostenpflichtigen Tarifen gedacht, und über die Tarife informieren wir dich im Voraus. Solange tTerm in der Beta ist, ist es für alle kostenlos.

Du kannst deine eigene Kopie von tTerm betreiben: Die AGPL erlaubt das. Aber die meisten brauchen ein Terminal und nicht noch einen Dienst, den sie selbst hosten, aktualisieren und sichern müssen.

So machen es auch andere offene Projekte. 2020 wechselte Plausible von MIT zur AGPL, damit Unternehmen auf seinem Code keine konkurrierenden Dienste aufbauen, ohne etwas zurückzugeben. 2021 wechselte Grafana von Apache 2.0 zur AGPL. Beide verkaufen eine Cloud-Version ihres offenen Codes.

Wo der Code liegt

Der gesamte Code von tTerm liegt in einer Organisation auf GitHub: github.com/tterm-net. Hier sind ihre Repositorys und wofür jedes da ist:

  • tterm-web
    tTerm Web, Seite und Server: der Kern, der deine Terminals am Laufen hält, das separate Programm, das Zertifikate signiert, und die Installer für Server und Computer.
  • tterm-app
    tTerm für deinen Computer: dieselbe Seite in einem eigenen Fenster, mit den Shells dieses Computers. Die Engine ist in Rust geschrieben, und macOS kommt zuerst.
  • tterm-agent
    Der Agent für Computer: Er verbindet einen Mac oder eine Linux-Maschine mit tTerm Web und mit dem Bot. Er baut die Verbindung selbst nach außen auf und öffnet keine Ports.
  • tterm-telegram
    Der Telegram-Bot, aus dem tTerm entstanden ist.
  • site
    Diese Website.
  • .github
    Die Seite der Organisation auf GitHub.

Die Installer sind kurz: Lies sie, bevor du sie ausführst.
