Neu: tTerm im BrowserLesen

Das Cloud-Terminal
für Server und Computer

Deine Terminals leben in der Cloud, nicht auf deinem Laptop: Klapp ihn mitten im Build zu, öffne tTerm auf dem Handy, und alles ist noch so, wie du es verlassen hast. Keine Schlüssel auf deinem Gerät, keine offenen Ports.

Kostenlos starten Open Source

Linux-ServerÜber normales SSH, mit einem Befehl auf dem Server

Computer mit macOS und LinuxAuch hinter NAT, ohne offene Ports

Jeder BrowserAuf Laptop, Tablet oder Handy

So funktioniert es

In drei Schritten zum ersten Befehl

01

Maschine hinzufügen

Ein Befehl auf dem Server, und er steht in deiner Liste. Ein Computer braucht einen kleinen Agenten, der sich von innen verbindet.

$ curl -sSL https://connect.tterm.net/s/… | sudo sh
02

Terminal öffnen

In jedem Browser. Tabs aus verschiedenen Projekten nebeneinander, und jede Maschine ist nur ein Cmd+K entfernt.

P/web-01A/api-prodP/MacBook
03

Arbeiten wie gewohnt

Deine Shell, deine Programme, sudo. Schließ den Tab, und das Terminal läuft weiter.

bashzshvimhtopgitdocker

Funktionen

Ein Terminal, das Befehle versteht

tTerm weiß, wo jeder Befehl beginnt und endet, wie er ausgegangen ist und wo du gerade bist. So kannst du mit der Ausgabe arbeiten, statt sie nur zu lesen.

~/appmain1.4 s
❯ git pull
Fast-forward
src/server.ts | 12 +++++++-----
1 file changed

Jeder Befehl ist ein Block

Exit-Code, Zeit, Verzeichnis und Branch. Einen Block kannst du komplett kopieren, einklappen oder erneut ausführen.

❯ docker compose logs -f api
→Vorschlag aus dem VerlaufTabVervollständigung

Eine Eingabezeile wie im Editor

Mehrere Zeilen, ein Verlauf über alle deine Geräte, Vorschläge und Tab. Vor einem gefährlichen Befehl fragt tTerm noch einmal nach.

Sicherheit

Wir speichern keine Schlüssel.
Wir öffnen keine Ports.

Zugriff auf deine Maschinen ist leicht vergeben und genauso leicht wieder entzogen. So funktioniert es.

Ein Zertifikat für zwei Minuten

Jede Verbindung bekommt ein eigenes SSH-Zertifikat mit deinem Namen darin, gültig nur für diesen einen Server. Deine Schlüssel brauchen wir nie.

Signieren strikt getrennt

Die CA-Schlüssel liegen in einem separaten Prozess ohne Netzwerk. Der Kern kann sie nicht lesen, nur um eine Signatur bitten, und jede Signatur wird protokolliert.

sshd_config bleibt unangetastet

Vertrauen ist eine einzige Zeile in der Datei authorized_keys eines Benutzers. Neu gestartet wird nichts.

Verbindungen von innen

Der Agent auf einem Computer baut die Verbindung selbst nach außen auf, deshalb sind keine eingehenden Ports nötig. Er lässt sich mit einem Befehl deinstallieren.

Keine Mittelsmänner

Die Seite und die Terminals verbinden sich direkt mit unserem Server in der EU. Cloudflare ist bei uns nur für DNS zuständig und sieht deine Befehle nie.

Open Source

tTerm Web und der Agent sind Open Source unter der AGPL. Das Installationsskript ist kurz: Lies es, bevor du es ausführst.

Für Teams

BALD

Sieh, wer was ausgeführt hat

Lade dein Team in ein Projekt ein und gib jeder Person eine Rolle. Schlüssel für deine Server musst du nicht mehr verteilen.

  • Projektrollen: Eigentümer, Admin, Mitglied und Betrachter.
  • Ein gemeinsames Protokoll: wer was wo und wann ausgeführt hat und wie es ausging.
  • Zuschauen: Schau jemandem aus dem Team ins Terminal, und die Person sieht immer, wer zuschaut.

Fragen

Muss ich etwas auf meinem Computer installieren?

Nein, ein Browser reicht. Etwas installieren musst du nur auf den Maschinen, mit denen du dich verbindest: auf einem Server genügt ein Befehl, auf einem Computer ein kleiner Agent.

Was speichert ihr?

Befehle und ihre Ausgabe für 30 Tage, um dir deinen Verlauf zu zeigen, und ein Protokoll der Anmeldungen. Schlüssel und Passwörter speichern wir nicht. Die Details stehen in der Datenschutzerklärung.

Was ist daran besser als an einem normalen SSH-Client?

Es funktioniert in jedem Browser und braucht keine Schlüssel auf deinem Gerät. Das Terminal bricht nicht ab, wenn du den Laptop zuklappst. Und jeder Befehl kommt als Block, der sich leicht kopieren und erneut ausführen lässt.

Wie entziehe ich tTerm den Zugriff?

Entferne den Server in tTerm, und tTerm entfernt seinen Zugriff dort selbst. Antwortet der Server nicht, zeigt tTerm den Befehl, der das auf dem Server erledigt. Wie du alles andere entfernst, was der Installer eingerichtet hat, steht ganz oben im Skript selbst. Den Agenten entfernst du mit einem Befehl vom Computer.

Was ist mit dem Telegram-Bot?

Er bleibt und funktioniert weiter: ein Terminal direkt im Chat, @tTermNetBot. Vorerst laufen Web-App und Bot getrennt.

Wie erreiche ich den Support?

Schreib an support@tterm.net. Wenn du eine Sicherheitslücke gefunden hast, schreib an security@tterm.net.
